## II. BỐ CỤC VỊ TRÍ CHUẨN 3 TẦNG (FIX LỖI BỊ NGƯỢC THỨ TỰ)

### 1. Nguyên nhân bị ngược trước đây
- Trước đây, hook `woocommerce_before_shop_loop` gọi HUSKY top panel (`[woof_search_options]`) và thanh sắp xếp trước, sau đó mới gọi shortcode `[woof]` (Tìm theo:).
- Hậu quả: Dải **Bỏ hết** bị đẩy lên trên cùng, kế tiếp là **Xếp theo:**, và **Tìm theo:** lại nằm ở dưới cùng (bị đảo ngược 180° so với mẫu GOBIKE).

### 2. Cấu trúc chuẩn sau khi tái cấu trúc
```
┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ TẦNG 1: Tìm theo:  [Thương hiệu ▼]  [Giá sản phẩm ▼]  [Loại ▼]  [Kích thước ▼]                        │
├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ TẦNG 2: [Bỏ hết ✕ (Nút đỏ)]  [Giá dưới 5.000.000đ ✕]  [Samebike ✕]  [ADO ✕]  [Địa hình ✕]  ...          │
├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ TẦNG 3: Xếp theo:  ( ) Tên A-Z   ( ) Tên Z-A   (●) Hàng mới   ( ) Giá thấp đến cao   ( ) Giá cao xuống │
└────────────────────────────────────────────────────────────────────────────────────────────────────────┘
                                                    ▼
                             LƯỚI SẢN PHẨM WOOCOMMERCE (5 CỘT)
```

### 3. Giải pháp kỹ thuật 2 lớp (PHP Template + JS DOM Reorder)
1. **Lớp PHP trong [category-none.php](file:///e:/1.%20D%E1%BB%B0%20%C3%81N%20TH%E1%BB%B0C%20T%E1%BA%BE%20%282026%29/wp-content/themes/flatsome-child/woocommerce/layouts/category-none.php)**:
   ```php
   // 1. Dòng 1: Tìm theo:
   if ( shortcode_exists( 'woof' ) && ! did_action( 'woof_before_filter' ) ) {
       echo do_shortcode( '[woof autohide="0" autosubmit="1" is_ajax="1"]' );
   }

   // 2. Dòng 3: Xếp theo:
   if ( function_exists( 'gobike_render_custom_sorting_toolbar' ) ) {
       gobike_render_custom_sorting_toolbar();
   }

   // 3. Hook mặc định của WooCommerce (nơi HUSKY tự động render duy nhất 1 dải Badges & Bỏ hết)
   do_action( 'woocommerce_before_shop_loop' );
   ```

2. **Lớp JavaScript trong [gobike-product-filter.php](file:///e:/1.%20D%E1%BB%B0%20%C3%81N%20TH%E1%BB%B0C%20T%E1%BA%BE%20%282026%29/wp-content/themes/flatsome-child/gobike-product-filter.php)**:
   Hàm `reorderGobikeFilterElements()` tự động di chuyển dải Badges & Bỏ hết vào giữa Tầng 1 và Tầng 3, đồng thời xóa triệt để bất kỳ bản sao trùng lặp nào:
   ```javascript
   function reorderGobikeFilterElements() {
       if ($('.woof_products_top_panel').length > 1) {
           $('.woof_products_top_panel').not(':first').remove();
       }

       var $redrawZone = $('.woof_redraw_zone').first();
       var $topPanel = $('.woof_products_top_panel').first();
       var $sortingToolbar = $('.gobike-custom-sorting-toolbar').first();

       if ($redrawZone.length) {
           if ($topPanel.length) {
               $topPanel.insertAfter($redrawZone);
           }
           if ($sortingToolbar.length) {
               if ($topPanel.length && $topPanel.is(':visible') && $topPanel.find('li').length > 0) {
                   $sortingToolbar.insertAfter($topPanel);
               } else {
                   $sortingToolbar.insertAfter($redrawZone);
               }
           }
       }
   }
   ```

## III. XỬ LÝ CÁC VẤN ĐỀ PHÁT SINH THỰC TẾ & TỐI ƯU HÓA CUỐI CÙNG

### 🔴 Vấn đề 1: Xuất hiện 2 nút "Bỏ hết" (1 cái trên, 1 cái dưới thanh Xếp theo:)
- **Nguyên nhân**: File `category-none.php` gọi `echo do_shortcode('[woof_search_options]');`, và bên dưới hook `woocommerce_before_shop_loop` của HUSKY lại gọi `[woof_search_options]` thêm một lần nữa.
- **Giải pháp xử lý**:
  - Gỡ bỏ lệnh gọi thừa trong `category-none.php`.
  - Thêm cơ chế JavaScript tự động kiểm tra và xóa bỏ bản sao thừa: `$('.woof_products_top_panel').not(':first').remove()`.
- **Kết quả**: Chỉ duy nhất 1 khối panel hiển thị ở đúng vị trí giữa.

### 🔴 Vấn đề 2: Các badge bị mất chữ nhãn, chỉ còn lại ô vuông đỏ có dấu `[✕]`
- **Nguyên nhân**:
  - HUSKY đặt toàn bộ nội dung chữ của badge (`Samebike`, `Giá dưới 5.000.000đ`, `GT20`...) bên trong thẻ `<span class="woof_remove_ppi">`.
  - Trong CSS trước đó có dòng `.woof_products_top_panel span.woof_remove_ppi { display: none !important; }` nên toàn bộ text nhãn bị biến mất, chỉ trơ lại dấu `✕` của pseudo-element `::after`!
  - Đồng thời selector `.woof_products_top_panel li:first-child a` đã vô tình ép màu nền đỏ của nút Bỏ hết lên badge đầu tiên.
- **Giải pháp xử lý**:
  - Đặt lại `span.woof_remove_ppi { display: inline !important; color: #fff !important; font-weight: 600 !important; }`.
  - Tách bạch: Màu đỏ chỉ áp dụng riêng cho nút Bỏ hết (`.woof_reset_button_2`, `a.woof_clear_all`).
- **Kết quả**: Tất cả các badge hiển thị đầy đủ tên giá trị bộ lọc, mang bảng màu 6 sắc rực rỡ luân phiên kèm icon `✕` chuẩn 100% như ảnh mẫu.

### 🔴 Vấn đề 3: Làm sao để ẩn nút "Reset" đi, chỉ giữ lại nút "Bỏ hết"?

#### 1. Hiện tượng thực tế
- Trên giao diện xuất hiện một nút **"Reset" màu xanh lá cây** (nền xanh chữ trắng) nằm ở phía cuối hàng **"Tìm theo:"**, đứng cạnh các ô chọn dropdown (Giá sản phẩm, Bộ lọc, Danh mục sản phẩm, Thẻ sản phẩm).
- Trong khi đó, ngay ở tầng dưới (dải Badges đang chọn), đã có sẵn nút **"Bỏ hết ✕" màu đỏ** (`#d0021b`).
- Việc tồn tại đồng thời cả 2 nút này gây dư thừa chức năng, làm rối mắt người dùng và phá vỡ cấu trúc thanh lọc tối giản, sang trọng của mẫu thiết kế GOBIKE.

#### 2. Nguyên nhân kỹ thuật cốt lõi
- Plugin HUSKY Products Filter (WOOF) theo cơ chế mặc định luôn gọi hàm `woof_show_btn($autosubmit, $ajax_redraw)` để sinh ra khối `<div class="woof_submit_search_form_container">` chứa nút `<button class="woof_reset_search_form">Reset</button>` ở cuối form lọc nếu không được can thiệp.
- Nút "Reset" xanh này là nút reset cấp form, trong khi nút "Bỏ hết ✕" màu đỏ ở dải Badges là thành phần của `<div class="woof_products_top_panel">`.

#### 3. Các giải pháp xử lý triệt để

##### ✅ Cách 1: Xử lý đóng gói trực tiếp bằng CSS trong `gobike-product-filter.php` *(Tối ưu nhất - Độc lập hosting)*
Ẩn toàn bộ các biến thể container và nút bấm của cụm Reset/Submit form trong vùng vẽ lại của HUSKY (`.woof_redraw_zone`):
```css
/* Ẩn hoàn toàn nút Reset màu xanh ở đuôi dòng 'Tìm theo:', chỉ giữ lại duy nhất nút 'Bỏ hết ✕' màu đỏ ở dải Badges */
.woof_redraw_zone .woof_submit_search_form_container,
.woof_redraw_zone .woof_reset_search_form_container,
.woof_redraw_zone .woof_reset_search_form,
.woof_redraw_zone button[data-name="reset"],
.woof_redraw_zone .woof_btn_default {
    display: none !important;
}
```

##### ✅ Cách 2: Bảo vệ 2 lớp bằng JavaScript DOM Cleanup
Trong hàm `reorderGobikeFilterElements()` của module `gobike-product-filter.php`, bổ sung thêm lệnh ẩn chủ động mỗi khi DOM được vẽ lại hoặc khi HUSKY hoàn tất một lượt lọc AJAX:
```javascript
// Đảm bảo ẩn triệt để nút Reset/Submit xanh ở dòng 'Tìm theo:' sau mỗi lần AJAX nạp lại
$('.woof_redraw_zone').find(
    '.woof_submit_search_form_container, .woof_reset_search_form_container, .woof_reset_search_form'
).hide();
```

##### ✅ Cách 3: Cấu hình qua WordPress Admin (Tùy chọn bổ trợ)
Nếu quản trị viên thao tác trực tiếp trên giao diện quản trị WordPress:
1. Vào **WooCommerce** ➔ **Cài đặt (Settings)** ➔ Tab **Bộ lọc sản phẩm (HUSKY/WOOF)**.
2. Tại tab **Cấu hình chung (Options)**:
   - Mục **Tự động lọc (Autosubmit)**: Đặt là `Có (Yes)`.
   - Mục **Vị trí nút tìm kiếm (Search button position)**: Chọn `Không hiển thị (None)`.
   - Mục **Ẩn nút Reset (Hide reset button)**: Chọn `Có (Yes)`.
3. Nhấn **Lưu cài đặt**. *(Nhờ có Cách 1 & Cách 2 trong code, hệ thống hoạt động hoàn hảo ngay cả khi chưa kịp bấm cấu hình trong WP Admin)*.

#### 4. Kết quả đạt được
- Thanh **"Tìm theo:"** (Tầng 1) hiển thị cực kỳ thông thoáng, tinh gọn, chỉ gồm tiền tố đỏ nổi bật và các nút dropdown thuộc tính bo góc sang trọng.
- Khi khách hàng chọn lọc sản phẩm, dải **Badges** (Tầng 2) hiển thị với các thẻ màu sắc phong phú và **duy nhất nút "Bỏ hết ✕" màu đỏ bo góc** chuẩn 100% theo bản thiết kế GOBIKE gốc. Bấm vào nút "Bỏ hết ✕" sẽ xóa sạch toàn bộ các tiêu chí đang chọn và khôi phục lại danh sách xe đầy đủ.

// Render thanh sắp xếp radio trực tiếp
